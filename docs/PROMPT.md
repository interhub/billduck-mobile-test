# 📜 BillDuck: требования и решения одним документом

Этот документ - задание, по которому ИИ-агент писал код под моим контролем. В нём требования тестового, решения, которые я принял до начала работы, и правила бренда. Правила кода лежат в `.claude/rules/` и ссылаются сюда.

## 🎯 Что строим

- 📱 Фрагмент мобильного приложения BillDuck на React Native + TypeScript: выбрать банковскую выписку (PDF или CSV), проверить её на телефоне, отправить байты на локальный mock-сервер, дождаться результата, пережить потерю ответа и перезапуск, безопасно удалить импорт.
- 🍏🤖 Нативный запуск на iOS и Android: симулятор iPhone и эмулятор Android. Живые телефоны не проверяются.
- 🛑 Стоп-факторы: утечка документа или секрета, второй job после повторной отправки, ложное «удалено».

### ✅ Матрица приёмки (обязана пройти на iOS и на Android)

| 🧪 Сценарий | 👀 Что видно |
|---|---|
| `happy` | файл реально отправлен, ответ 202 не выдаётся за готовый отчёт, после `ready` видны 2 позиции и сумма за месяц: `151.99 AUD / month`, на русском `151,99 AUD в месяц` |
| `lost_ack` | первый POST создал job без ответа, приложение само нашло job по ключу (после повтора и после перезапуска), `newJobs = 1` |
| `stale_status` | после `ready` (ревизия 3) пришёл `processing` (ревизия 2), экран не откатился, в ленте ответов он помечен как устаревший и пропущенный, это закреплено тестом |
| `delete_failure` | DELETE вернул 503, экран не говорит «удалено», после переключения на `happy` повтор с тем же ключом доходит до `deleted` |
| `spoofed.pdf`, `oversize.csv` | оба отклонены до POST, `createRequests` не изменился |

## 🔌 Контракт mock-сервера

- 🌐 Адрес `http://127.0.0.1:8787`, проверка живости `GET /health`. Android-эмулятору нужен `adb reverse tcp:8787 tcp:8787`.
- 📤 `POST /imports`: тело - сырые байты, `Content-Type: application/octet-stream`, `Idempotency-Key` (8-128 знаков), `X-File-Name` (1-255 знаков). Ответ 202 `{jobId, status: "queued", revision: 1}`. Те же ключ и байты дают тот же job (`duplicateHits`), тот же ключ с другими байтами - 409, нет ключа или имени - 400, больше 10 МиБ - 413, не PDF и не CSV - 415.
- 🔎 Формат сервер узнаёт по байтам: PDF начинается с `%PDF-`, CSV - с `date,description,amount\n` в первых 24 байтах без `\r` (CSV с `\r\n` и с BOM отклоняется).
- 🔑 `GET /imports/by-key/{key}`: 200 и состояние job или 404 «пока не найден».
- 📊 `GET /imports/{jobId}`: `queued` r1, затем `processing` r2, затем `ready` r3 с валютой и двумя позициями.
- 🗑️ `DELETE /imports/{jobId}` со своим `Idempotency-Key`: 202 `deleting` r4, через секунду `deleted` r5. Неизвестный job - 404.
- 🧪 Служебные маршруты: `POST /__test/reset`, `POST /__test/scenario` (`happy`, `lost_ack`, `stale_status`, `delete_failure`), `GET /__test/state` со счётчиками `createRequests`, `newJobs`, `duplicateHits`, `acceptedBytes`, `deleteRequests`.
- 🎭 Тонкости: `lost_ack` рвёт ответ на каждый новый job, пока режим включён; `stale_status` отдаёт устаревший `processing` только на второй GET после `ready`; после `/__test/reset` номера job начинаются с `job-demo-001`; mock хранит состояние в файле и переживает свой перезапуск.
- 🚫 Код и фикстуры набора не меняются никогда.

## 🧱 Стек

- ⚛️ Expo SDK 57, React Native 0.86 (новая архитектура), React 19.2, React Compiler, Hermes, TypeScript в строгом режиме.
- 🧭 React Navigation 7, один нативный стек. 🗃️ Zustand для состояния экрана. 💾 AsyncStorage для операции импорта.
- 📁 `expo-document-picker` для выбора файла, новый API `expo-file-system` для копии и потоковой загрузки (`file.createUploadTask` с `sessionType: 'foreground'`), `expo-image` для картинок, `react-native-svg` только для логотипа, значки Phosphor.

## 🔄 Операция импорта

### 🧩 Модель

- 1️⃣ Одна активная операция за раз. Фазы: `validating`, `rejected`, `confirming` (только в памяти), затем `uploading`, `reconnecting`, `server_unavailable`, `not_received`, `queued`, `processing`, `ready`, `failed`, `replacing_previous`, `deleting`, `delete_failed`, `deleted`, `gone_on_server`.
- 💾 С фазы `uploading` на диске хранятся только операция (ключ, `jobId`, ревизия, фаза, размер и формат, сгенерированное имя для сервера) и список отменённых загрузок на уборку. Настоящее имя файла и найденные платежи не хранятся: после перезапуска платежи читаются с сервера заново.
- 🧠 Каждая смена фазы проходит через чистый редьюсер, нигде фаза не присваивается руками. Редьюсер и защита ревизий покрыты тестами первыми.

### 📤 Отправка

- 🔑 Ключ повтора создаётся один раз при открытии экрана подтверждения и записывается на диск до первого POST. Двойное нажатие «Отправить» даёт один ключ и один запрос.
- 🔁 Если есть прошлая выписка, она сначала удаляется с подтверждением сервера. Удаление не прошло - новая не уходит, экран говорит об этом честно и предлагает «Повторить».
- 🌊 Байты идут с диска потоком, а не через память JS. 202 - единственный успех; 202 никогда не показывается как готовый отчёт.
- ⛔ Ответ 4xx - честное «Ошибка» без повторов. Всё остальное (нет ответа, обрыв, таймаут, 5xx) - фаза «Переподключаемся…».

### 🔦 Восстановление после потерянного ответа

- 🔎 До трёх попыток через 1, 2 и 4 секунды: `GET` по ключу. Нашёлся - берём job; 404 - POST с тем же ключом и теми же байтами. Человек видит только «Переподключаемся…».
- 🔌 Все попытки без ответа - «Сервер недоступен» с «Повторить» и тихой «Отменить загрузку».
- ♻️ После перезапуска приложение только читает по ключу и никогда не отправляет файл само: нашёлся job - продолжаем, 404 - «Файл не дошёл до сервера» с «Отправить ещё раз».
- 🧹 «Отменить загрузку» сразу удаляет копию файла и кладёт загрузку в список уборки: как только сервер снова отвечает, job по ключу удаляется, если он успел появиться.

### ⏱️ Опрос и лента ответов

- 🔁 `GET` каждые 500 мс, пока `queued`, `processing` или `deleting`; после ошибки пауза растёт до 4 секунд. Две неудачи подряд - «Переподключаемся…», 30 секунд без ответа - «Сервер недоступен».
- 📲 В фоне опрос стоит, при возврате статус читается сразу.
- 🧾 После `ready` статус читается ещё раз при возврате в приложение, при открытии отчёта и жестом «потянуть вниз»: так `stale_status` виден вживую.
- 📜 На экране статуса лента всех ответов сервера: статус, ревизия, время. Пропущенный устаревший ответ остаётся в ленте с пометкой «Устарел, пропущен».

### 🛡️ Ревизии и привязка ответов

- 📈 Состояние сервера принимается, только если ревизия больше сохранённой. Исключение: `ready` той же ревизии принимается, если платежей на телефоне нет.
- 🔗 Каждый ответ привязан к операции и job, для которых был запрос. Поздний ответ после удаления, замены или отмены выбрасывается.
- ❓ 404 на `GET /imports/{jobId}` - «Нет на сервере», а не «Удалено». Номер job после сброса mock может принадлежать чужой загрузке, поэтому перед чтением статуса вне опроса и перед удалением ключ проверяется по `GET /imports/by-key/{key}`.

### 🗑️ Удаление

- 🔑 Свой ключ удаления создаётся и записывается до первого DELETE, каждый повтор идёт с тем же ключом.
- ✅ «Удалено» показывается только после `GET`, вернувшего `deleted`. 503 или другой отказ - «Не удалено. Сервер не подтвердил, данные пока на нём.» и «Повторить».

### 📁 Временные копии

- 🗂️ Копия файла живёт только в `Caches/imports/` под номером операции, никогда под настоящим именем. Копия выбора файла и папка `-Inbox` на iOS удаляются сразу.
- 🧽 Копия удаляется при отказе проверки, при отмене на экране подтверждения, сразу после подтверждения job сервером, при отмене загрузки и после удаления импорта. При каждом запуске удаляется всё, на что не ссылается активная операция.

| # | 🧪 Случай | ✅ Ожидание |
|---|---|---|

| 2 | Перезапуск во время отправки | только `GET` по ключу, `createRequests` не растёт |
| 3 | `lost_ack` с повтором и с перезапуском | `newJobs = 1` |
| 4 | Mock выключен во время отправки, опроса и удаления | честные состояния, после запуска mock всё продолжается само или по «Повторить» |

| 6 | `stale_status` | экран не откатывается, пропущенный ответ виден в ленте |
| 7 | `delete_failure`, потом `happy` | честное «не удалено», повтор с тем же ключом доходит до `deleted` |
| 8 | Поздний ответ после удаления, замены или отмены | выброшен |
| 9 | Новая выписка, а удаление старой падает | новая не отправлена, честный текст |
| 10 | «Отменить загрузку» при выключенном mock | после запуска mock загрузка удалена, если дошла |

| 14 | Отмена выбора файла, нечитаемый файл | спокойный возврат без ошибки и без копий |
| 15 | Система стёрла копию файла до выяснения исхода | честный текст, без 409 и без второго job |
| 16 | 4xx от сервера на отправку | «Ошибка» без бесконечных повторов |
| 17 | Уход в фон во время отправки и опроса | после возврата всё продолжается |

| 19 | Самый крупный шрифт, самый маленький экран, тёмная тема, «Уменьшить движение» | главные действия доступны, анимации выключены |

## 🔒 Приватность и логи

- 🙈 В логи, тексты ошибок и на сервер не попадают байты файла, его настоящее имя, пути к файлу и описания операций. На сервер уходит сгенерированное латинское имя вида `statement-20261029-1432.pdf`.
- 🏷️ На экранах вместо имени файла - название, собранное при отрисовке: `Statement · 29 Oct, 14:32 · PDF · 2.4 KB` / `Выписка · 29 окт, 14:32 · PDF · 2,4 КБ`. Настоящее имя видно только на экране подтверждения.
- 🪵 Один логгер с закрытым списком полей: тип операции, `job_id`, фаза, ревизия, формат, размер в КБ, вид ошибки, HTTP-статус, номер попытки. В релизной сборке он молчит. Аналитики и отчётов о падениях нет.
- ☁️ `android:allowBackup` выключен. Разрешение одно: интернет. HTTP разрешён только к `127.0.0.1` и `localhost`.

## 🎨 Бренд

### 🏷️ Имя и голос

- 🦆 **BillDuck** на обоих языках. По-английски «bill» - и клюв, и счёт. Слоган: `Where does my money go?` / `Куда уходят мои деньги?`.
- 🧮 Уточка - спокойный внимательный бухгалтер. Главная ценность - честность: приложение говорит только то, что точно знает.
- ✂️ Тексты короткие и спокойные: что происходит и что можно сделать. Без «Oops!», без восклицаний, без эмодзи в интерфейсе, без финансового жаргона. Цифры только из данных сервера.
- 🌐 Русский, если первый язык системы русский, иначе английский. Все строки в одном файле переводов. Язык перечитывается при возврате приложения на передний план.

- 🚦 Статус - всегда значок, слово и цвет вместе, никогда только цвет.

### 🔤 Шрифты, формы, движение

- 🔤 Unbounded SemiBold - логотип и один короткий заголовок экрана; Geist Regular и Medium - интерфейс; Geist Mono - суммы, даты, размеры. Все три с кириллицей.
- ⬜ Скругления 10 (кнопки), 16 (карточки), 24 (листы). Отступы по сетке 4: 4, 8, 12, 16, 24, 32. Рамки 1 пиксель, тени почти не используются. Кнопки не меньше 44 точек на iOS и 48 на Android.
- 🎬 Движение 150-250 мс по кривой `cubic-bezier(0.16, 1, 0.3, 1)` или пружиной (жёсткость 100, затухание 20). Смена статуса плавно перетекает. При «Уменьшить движение» анимации выключены.
- 🔠 Тексты растут вместе с системным шрифтом, экраны прокручиваются, главные кнопки закреплены внизу. Длинное слово на самом крупном шрифте не рвётся посередине.

### 🦆 Логотип, иконка, иллюстрации

- ✒️ Логотип нарисован вручную кодом SVG: уточка в профиль, жёлтое тело, графитовая линия, клюв - сложенный чек с зубчатым краем; рядом надпись `BillDuck` шрифтом Unbounded.
- 📱 Иконка и заставка: глянцевая 3D-уточка с белым чеком в клюве на графитовом фоне `#1A1814`. У Android отдельный передний план с полями, уточка целиком в центральном круге.
- 🖼️ Картинки экранов - изометрия тонкой графитовой линией с белыми гранями и ровно одним жёлтым предметом; тёмный вариант собран из той же картинки (светлые линии, прозрачный фон). Уточка везде один и тот же персонаж, текста и цифр на картинках нет.
- 📋 Где какая картинка: пустой главный экран, проверка файла, отказ, ожидание и обработка, готово, переподключение, сервер недоступен, удаление, удалено. Одна картинка на экран, до 280 точек в ширину; на крупном шрифте или маленьком экране она уменьшается вдвое или прячется.
- 🧰 Картинки сгенерированы нейросетью по промптам с эталоном уточки, фон вырезан скриптом, готовые файлы `@2x` и `@3x` до 150 КБ лежат в `assets/illustrations/` и `assets/images/`.

## 🛠️ Как работать

- 🗺️ Пошагово: окружение, репозиторий, каркас, основа, ядро с тестами, интеграционные тесты, нативный слой файлов, экраны и проверка на iOS, проверка на Android, бренд, финальный прогон, отчёт, сдача. Шаг закрыт, только когда его проверка подтверждена выводом команды или кадром; после шага коммит.
- ✍️ Коммиты на английском, от моего имени. Комментарии в коде на английском, документы для проверяющих на русском.
- 🧩 Нативные папки `ios/` и `android/` создаёт prebuild; всё нативное - только через config-плагины в `plugins/`.
